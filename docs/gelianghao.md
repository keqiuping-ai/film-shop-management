# 哥俩好：同服务器的朋友聊天模块

状态：2026-09-18 完成最新 origin/main 上的隔离发布验证，用户已授权部署到原 Railway 服务。

## 入口与复用

访问现有贴膜店域名下的 `/gelianghao/`。不创建第二个 HTTP 监听器，不申请额外服务器或通信供应商。
复用 server.js 的密码哈希校验、HTTP 服务、SSE 实时推送函数及现有 DATA_DIR 持久化磁盘。openEventStream 增加可选连接集合和会话有效性回调，旧调用保持原默认行为。朋友连接不加入公司事件集合，不接收业务数据变更。

首次开通输入现有贴膜店老板账号及密码验证权限，再创建独立的哥俩好账号。后续只能凭一次性邀请注册；邀请码七天过期、可撤销，只有哥俩好管理员可以创建。公司员工或客户不会自动成为朋友，朋友账号也不会写进公司的 users 集合。

## 第一版范围

- 邀请注册、独立账号密码、登录、退出及修改密码。
- 已受邀的朋友列表、一对一私聊、多成员朋友群。
- 文字、图片、视频、文件和最多 60 秒的语音消息；附件最大 20 MB。
- SSE 实时刷新、重连、未读计数及已读状态。
- 电脑两栏布局和手机独立会话页面。
- 可选设备本地中英翻译，点击单条消息翻译，不发送到云端 AI；只在支持 Translator API 的浏览器可用，手机不承诺可用。
- 系统通知只在网页仍运行且获准通知时提供；未实现关闭网页后的 Web Push。
- 一对一语音及群语音：顶部电话入口、选择群成员、来电、接听、拒绝、静音、恢复声音、收起、挂断和掉线清理；复用原 LiveKit 配置与 SDK，朋友通话房间和身份使用 glh- 前缀。
- 按住说话、松开发送、上滑取消，最长 60 秒；权限弹窗期间松手不误发，短按不发送，发送语音保留文字草稿。
- 不录制通话，不调用 AI 转写、摘要或督办；仅保存通话状态元数据，24 小时清除。
- 未采用端到端加密。服务器拥有者具有读取存储的技术能力。

## 24 小时保留与不备份

朋友数据位于 `DATA_DIR/gelianghao/chat.sqlite`，附件位于 `DATA_DIR/gelianghao/files/`，从不写入贴膜店的 `db.json`，不进入现有手动、每日或迁移 JSON 备份。

发送时间由服务端生成，消息发送满 24 小时后禁止读取，并清除消息和对应附件，对双方和所有群成员生效。服务启动（已有聊天库）、每分钟及每次聊天请求均执行清理（空闲时物理清理最多约延后 60 秒）；附件读取必须验证登录与会话成员权限，过期文件旧链接失效。未发送的孤立附件一天后清理。客户端不持久化消息或翻译，不注册离线消息缓存；页面每秒清理已显示的过期消息。请求响应使用 no-store。

SQLite 使用 DELETE 日志和 secure_delete，减少删除内容残留；这不是磁盘取证层面的绝对擦除承诺。已下载、截图、另存的副本无法远程删除。

**平台检查（2026-09-18）：** 已登录现有 film-shop-management 的 production 服务，在 Backups 页面确认显示 `No backup schedule`，没有启用平台自动卷备份。本次未更改备份设置或创建卷快照。未来若启用整卷快照或手动卷备份，整个 DATA_DIR 仍可能被包含；应用排除不能控制这些操作。未来增加整目录备份时必须明确排除 `gelianghao/`。
