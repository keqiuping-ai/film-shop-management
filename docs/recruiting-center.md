# 招聘与面试中心

入口为电脑管理端的「功能模块 → 招聘与面试中心」。招聘档案与客户客资分开保存，招聘短信复用系统现有 Twilio 账号。新建预约默认线上视频面试；到店为备用方式，地址为 `3212 Santa Monica Blvd, Santa Monica, CA 90404`。所有面试时间按 `America/Los_Angeles` 展示和安排，存储使用带时区的时间。

## 操作流程

### 简历优先与资料来源分离（2026-09-19）

- 应聘者详情主阅读区固定为左侧「简历原文」、右侧「AI 中文翻译」。桌面翻译前后均为等宽双栏；窄屏上下排列，未翻译时不显示大块说明或空的译文框。
- 翻译按钮在右侧，只处理左侧保存的 `resumeText`，不翻译或拼入经验摘要、跟进备注和评分。复用已有分段翻译、失败续译及身份/候选人/文本绑定保护；不自动发出请求，不覆盖原文，不发送消息。
- PDF 原件和简历来源链接在左侧。没有原文文字时明确标明尚未提供或 PDF 尚未提取，翻译不可用，绝不以内部摘要替代原文。
- 原有经历整理、经销商资源、跟进备注保留在下方默认收起的「内部整理与跟进（非简历原文）」；题库、逐题评分和六维评分保留在「面试记录与评分（内部参考）」。
- 未标明来源的内部记录不推定为候选人原话或 AI 分析。主阅读区的 AI 译文只作翻译，不称为分析或推荐。此调整不迁移、删除或修改候选人数据，不改 API、邮件、短信或视频间。

### 招聘步骤

1. 新增应聘者，填写姓名、手机、邮箱、应聘职位和来源；补充履历、经销商关系、到岗时间、全兼职意愿等工作相关资料。
2. 打开档案先看到四步卡片：发送邀约、确认时间、线上面试、记录与评分。可选择短信或邮件邀请；只有邮箱、没有手机的人也可走邮件渠道。邀请入口只预填英文草稿，询问面试意愿和时间；必须生成英文预览并人工核对后才能发送。短信的手机号、同意来源、退订和通道限制仍生效，不得虚填同意。
   - 发送确认已合并到「确认发送英文短信」按钮，不再要求额外勾选「我已核对」。预览本身不会发送短信；修改草稿后须重新生成预览，短信授权及退订检查不变。
3. 收到回复后，保存面试时间、方式和面试官。新预约默认为线上，线下地址不会进入线上邀请；保存预约本身不会通知应聘者。
4. 对方确认后，将预约标记为「已确认」。收到普通回复不会自动替对方确认时间。
5. 在预约控制台保存并生成一次性链接，选择英文短信或邮件将候选人链接带入草稿，核对后单独发送。生成新链接会使旧链接失效。面试官进入已有视频面试室；这几个操作互不代表消息已送达或候选人已加入。
6. 加入或到场后可人工标记「已加入 / 已到场」，完成后填写逐题评分或六项评分及事实依据。每项 1–10 分，未核实保持空白。未加入可询问连接问题或改期；修改时间或方式后需重新确认。录用等状态由招聘人员主动选择。

### 线上优先与旧预约兼容（2026-09-19）

- 预约 API 新增可选 `mode: "online" | "in_person"`。新界面明确提交 `online`；旧调用和历史缺失字段仍按 `in_person`，不自动转换旧到店预约、不批量重写资料。线上地址可空；到店地址仍必填。
- 详情页把主要动作放在资料上方，到店入口收进备用折叠区。紧凑资料卡、申请/录入时间区别、简历原件及中英对照保留。
- 在线确认、提醒和未加入模板使用视频面试措辞；旧到店预约仍使用到店措辞。自动提醒不会生成新链接，只提示使用单独收到的链接。实际视频、AI 和短信服务沿用已有配置，本轮不改密钥或环境。

简历支持文字、外部链接及最大 5MB 的 PDF 上传。上传文件保存在当前 `DATA_DIR/recruiting-resumes`，查看须登录并具有招聘查看权限。做完整备份时需要同时保留数据库和此目录；数据库 JSON 备份只含文件信息。

每次预约的自动短信提醒默认关闭。开启后，仅对候选人已确认的预约在面试前约 24 小时、2 小时各提醒一次，并检查短信授权及退订状态。服务恢复时不补发已经错过的旧提醒，也不在面试后自动发送迟到催促。手动邀约和迟到跟进可在对话中编辑后发送。测试/演示环境用 `RECRUITING_REMINDERS_ENABLED=false` 关闭后台自动发送；生产环境也可使用此开关统一关闭提醒。

六项评分为销售能力、经销商资源、首周开发计划、沟通表达、执行力和岗位匹配。两个业务方向是把经销商车辆引入门店施工，以及向有施工条件的商家销售汽车膜。评分应记录具体案例和可核实信息，不使用受保护特征，也不把口头承诺直接视为成交业绩。

### 邮件邀约渠道（2026-09-19）

- 邮件窗口有独立的主题、正文、英文预览和发送记录。中文主题或正文沿用已配置的 AI 翻译；两项都完成、核对收件人后，再点击最终发送按钮。英文可直接预览，不需要额外勾选。
- 邮件不要求手机号或短信授权。收件邮箱来自应聘者档案，不接受客户端指定其他收件人、抄送、密送或发件人。修改草稿、邮箱或登录身份会使旧预览失效；同一发送编号不能重复投递。
- 应聘者明确要求停止邮件联系时，在编辑资料中记录停止联系及依据，之后系统邮件与打开邀请草稿均会被阻止。这与短信退订分别保存，不虚构候选人的授权。
- 邮件记录保存在独立的 `candidate.emailMessages` 中，不混入短信收件、号码冲突、未读回复或 Twilio 回执。邮件服务接受请求仅显示为已提交，不代表已投递、已阅读或对方已确认面试。
- 首版不包含 Gmail/IMAP 邮件收件同步或自动确认预约。回复请到界面显示的回复邮箱查看，再人工保存对方确认的时间。Indeed 转发邮箱会标识为中转地址，是否转交成功仍需在原邮件或 Indeed 核实。
- 系统直发复用现有 Resend 服务配置，不修改员工排班邮件。配置要求：`RESEND_API_KEY`；发件地址依次读取 `RECRUITING_FROM_EMAIL`、`RESEND_FROM_EMAIL`、`REMINDER_FROM_EMAIL`；回复邮箱读取 `RECRUITING_REPLY_TO_EMAIL` 或 `RESEND_REPLY_TO_EMAIL`。需在服务商验证发件身份，并明确设置可收信的回复邮箱；不会推断或伪造发件地址。
- 未配置完整时，系统直发按钮明确停用；仍可准备、翻译和核对邀请，然后选择「在邮箱中打开英文邀请草稿」。这只唤起邮件客户端，由操作人另行发送，系统不会将其记作已发出。实际可支持的草稿长度受邮件客户端限制。
- 发送超时或结果未知会保留待核实记录；不要重新创建发送任务来猜测重发。权限、禁止中文、收件人绑定及防重复校验同时在服务端执行。测试全部使用模拟邮件服务，不给真实应聘者发测试邮件。

## 权限及数据

- `recruitingView`：查看应聘者、面试、简历和沟通记录。
- `recruitingEdit`：维护档案、预约、评分和发送招聘短信／邮件；需要同时具备查看权限。
- 老板和经理默认具有上述权限，其他员工由老板在账号权限里单独授权。
- 招聘数据经独立 API 返回，不加入普通客户列表、客户销售统计或客户端数据。
- 招聘短信入站和送达回执按手机号、平台消息编号关联，重复回执不重复插入；短信入站不会启动客户促销或客户 AI 回复。
- 如号码同时出现在客户资料和招聘档案中，系统提示冲突并阻止不明确的发送。旧客户交流中的应聘记录不会被静默搬移或删除。
- 老板确认属于本人控制的测试号码后，可在该档案短信窗口开启 **24 小时测试**。例外绑定该档案 ID 与完整号码，记录批准人、原因、批准/到期时间，可随时关闭；换号自动失效。不会替代短信授权、退订、英文预览、号码核对或防重复发送保护。
- 测试只放行人工招聘短信，不开放共号的自动提醒或客户端发送。测试窗口内的新回复仅进对应招聘档案，不触发客户 AI/促销；测试前历史、到期或撤销后的共号回复继续隔离，旧客户记录及已有隔离记录不迁移、不删除。开启/关闭测试本身不发送短信。
- 邀请、提醒和失败状态只表示对应沟通步骤，不代表对方接受、到店或录用。
- 平台发送结果未知时会保留待核实记录，重复提交同一发送编号不会再次发送；收到平台送达回执后更新原记录。

## 本地验收

### 多面试官视频间（2026-09-19）

- 同一场预约使用同一视频房。面试官通过 `recruiting-interview.html?interview=...` 进入，须先登录具有招聘查看权限的系统账号；此链接不含登录凭据，也不是候选人的一次性邀请链接。增加面试官无需重新生成候选人链接。
- 每个面试官页面具有独立入会标识，即使同一账号在多个设备打开也不会使用相同视频身份；同一页面重连保留其身份。姓名和转写归属由服务器按登录账号确定，不接受客户端冒充候选人或其他面试官。
- 房间按参与者分别显示视频、姓名、角色与在线人数。摄像头关闭时保留该参与者占位；离开时移除其画面和音频。
- “离开面试”只断开自己的音视频，不结束其他人的会话；“结束所有人的面试”独立确认，且仍要求招聘编辑权限。仅有查看权限的面试官可以入会，但不能保存转写、请求分析或结束整个房间。
- 候选人仍通过原有一次性链接、说明确认及原浏览器会话重连。候选人接口不返回内部用户编号、招聘档案、简历笔记或 AI 评分。
- 不迁移候选人数据、不修改短信授权、不新增短信或邮件发送。多人 UI 使用本地模拟参与者验收；实际多设备音视频质量须在真实面试前测试。

### 人工控制的 AI 英语提问试用版（2026-09-19）

- 面试官控制选题、提问、停止、重读及回答记录，不自动跳题或开始录音。候选人入会页直接提供“同意并加入 AI 辅助面试”和“仅视频通话、不启用 AI 录音”两种选择，不再重复勾选。说明明确披露 AI 英语语音、回答录音、OpenAI 处理、文字保存与人工决定；只有候选人主动选择 AI 入会才保存可选同意。旧会话、重新连接及视频入会都不会自动补成同意；房间内可单次按钮启用或随时撤回。
- 只有具备招聘编辑权限的面试官能取得 AI 控制权。同一房间服务端只允许一个有效控制租约，同一账号的不同标签页也不能同时控制。失去租约、断网、离开或撤回同意时停止音频与记录，不自动恢复。
- 英语题目通过 OpenAI 语音接口合成，使用 `onyx` 男声，并作为独立音轨发布到现有 LiveKit 房间；不是只在面试官本机播放。AI 语音有明确披露，不模仿真实个人。已配置的 OpenAI 密钥仅留在服务端，语音默认 `gpt-4o-mini-tts`，回答转写默认 `gpt-4o-mini-transcribe`，文本翻译/分析沿用系统既有模型；不新建账号或服务。
- 面试官打开页面后，只为当前选中的题库提前准备通用英语题目，优先当前题，显示准备数量和失败重试入口；不会提前播放或录音。服务端对相同题目合并生成并缓存，浏览器提前下载，点击播报时优先使用已准备的音频。缓存绑定完整题文、模型、男声及朗读指令；缓存不包含候选人录音、简历或私人追问。第一次准备或临时追问仍可能需要等待，失败不会无限重试或伪装成已就绪。实际播报仍逐次检查房间、控制权和同意状态。
- 中文追问先生成英文预览，面试官核对后才朗读。改动草稿后必须重新生成/核对，不自动把 AI 建议读给候选人。
- 这一版是逐题记录，不是连续实时字幕：问题读完后手动开始记录候选人的麦克风音轨，停止后才转写并生成中文对照。最长单段两分钟。不会混录面试官或 AI 音轨；建议参与者使用耳机，避免扬声器回声进入候选人麦克风。
- 回答音频会提交 OpenAI 处理；应用不把原始录音存入数据库或文件。保存的是明确标注的英文转写、中文译文、对应问题和转写来源。英文转写仍需核对，不能当成绝对准确的逐字记录；中文翻译失败时保留英文，不伪装成功。请求结果未确认时可用同一请求查询保存结果，不会重复调用提供商；已明确失败或取消时需丢弃片段后手动重新提问、录制，不自动重发音频。刷新或退出会丢失页面内未保存音频。
- 总结与逐题评分仅在人工点击后生成，不自动录用/拒绝，不修改候选人原简历和人工评分。AI 问题、内部备注与候选人的回答分开；分析只依据岗位相关回答和明确证据，不使用口音、外貌、情绪推断或受保护特征。没有对应回答证据的评分应为空。
- 开发验证使用虚拟面试、模拟提供商和合成音轨，不能代替真实双设备耳机试听、浏览器录音兼容性与正式 OpenAI 额度/模型权限检查。正式面试前应先用测试候选人完成一次提问、听音、停止、回答保存与撤回同意流程；不应直接用真实候选人试故障。
- 首版验收（简化入会与预加载之前）：完整 `npm run test:recruiting` 通过；语音后端 24、语音前端模拟 11、视频 17、逐题分析 7 项通过。本地 Chromium 使用真实 WebAudio/MediaRecorder 与合成音轨，确认发布音轨有非零音频、停止/重读、手动回答提交、中英分栏、改稿失效及撤回同意丢弃片段；桌面及 390px 候选人界面无横向溢出。所有外部提供商/房间连接、真实麦克风和正式数据写入均禁用。
- 男声与预加载版本验收：完整 `npm run test:recruiting`、`test:portal-safety` 通过；语音、视频及分析共 82 项，隔离 HTTP 集成 231 项检查通过。新增测试覆盖同题合并、持久缓存及损坏回退、队列超时、严格音频键、私人追问不缓存、明确入会选择、重连不补授同意、预加载不播放/录音及撤回后的结果丢弃。本地 Chromium 确认入会前已准备 1/1 合成题音频、播报使用已准备音频并发布非零音轨，候选人可无勾选视频入会、一次按钮启用/撤回，重连仍保持视频-only。未调用真实 OpenAI、录制真实麦克风或更改正式候选人；男声音色及真实双设备听音仍需测试。前端版本标记 `20260919-male-preload-1`。
- 官方接口依据：[OpenAI 语音合成](https://developers.openai.com/api/docs/guides/text-to-speech)、[OpenAI 音频转写](https://developers.openai.com/api/docs/guides/speech-to-text)、[LiveKit 自定义音轨](https://docs.livekit.io/reference/client-sdk-js/)。

### 短短信与发送原因提示（2026-09-18）

- 招聘短信没有最低字数要求：去除首尾空白后，1–1600 个字符均可提交；短消息不会补字或自动扩写成模板。1600 是上限，不是必须填满的目标。
- 字数提示明确显示英文预览的字符数及上限。发送按钮旁持续显示具体阻止原因，包含缺少/无效手机号、同意记录不完整、退订、通道未启用、未预览、未人工核对、收件人改变或正在处理。
- 前端核对美国手机号格式及短信同意来源，与后端既有保护保持一致。只有邮箱不能发送短信；应先补充真实手机号或改用已授权的邮件渠道，不能虚填号码或同意。
- 英文预览、人工确认、汉字拦截、号码冲突、退订及防重复发送保护不变。只运行虚拟数据和模拟服务测试，不向真实候选人发送测试信息。
- 验收：招聘测试全部通过（OpenAI 模拟 21、翻译/发送单元 138、日期 219、既有界面 14、短信界面 40、隔离 HTTP 182）。本地浏览器用虚拟候选人验证 `Hi` 核对后可提交到模拟服务；缺少手机号及同意记录时，`OK` 核对后仍显示具体拦截原因。

### 时间排序与大幅简历阅读（2026-09-17，已批准发布，线上验收待完成）
